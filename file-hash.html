파일 해시 확인 · SHA-256 · MD5 체크섬

내려받은 파일이 배포처가 올린 것과 같은지, 전송 중 깨지지 않았는지 확인합니다. 파일의 SHA-256·SHA-512·SHA-1·MD5 값을 계산하고, 적어 둔 체크섬을 붙여 넣으면 같은지 바로 알려 줍니다.

🔒 파일이 서버로 업로드되지 않습니다
#️⃣ 파일을 끌어다 놓거나 클릭해서 선택하세요 어떤 파일이든 · 여러 개 가능 · 수 GB 파일도 조각으로 읽어 계산합니다
대소문자·공백은 무시합니다. 어느 알고리즘 값이든 일치하면 표시합니다.

    글자의 해시

    SHA-256-
    SHA-1-
    MD5-
    SHA-512-
    줄 끝의 줄바꿈까지 그대로 계산합니다. 리눅스의 echo 는 끝에 줄바꿈을 붙이므로 값이 다르면 그 차이입니다.

    해시는 내용이 같은지 확인하는 도구이고 암호가 아닙니다. 안전한 비밀번호는 비밀번호 생성기에서 만드세요. 두 글의 어디가 다른지 보려면 텍스트 비교입니다.

    체크섬을 왜 확인하나

    프로그램 설치 파일이나 운영체제 이미지를 내려받으면 배포처가 SHA-256 값을 함께 적어 둡니다. 내려받은 파일의 값이 그와 같으면 전송 중 한 바이트도 바뀌지 않았고, 누가 중간에서 다른 파일로 바꿔치기하지도 않았다는 뜻입니다. 한 글자만 달라도 해시는 완전히 다른 값이 되므로, 앞뒤 몇 글자만 눈으로 비교해도 충분합니다 — 이 페이지는 전체를 대조해 줍니다. 같은 원리로 백업한 파일이 원본과 같은지, 메일로 받은 문서가 중간에 바뀌지 않았는지도 확인할 수 있습니다.

    어떤 알고리즘을 쓰나

    SHA-256 — 지금 표준. 배포처 체크섬은 대부분 이것입니다.
    SHA-512 — 더 긴 값. 일부 리눅스 배포판이 씁니다.
    SHA-1 · MD5 — 오래된 방식으로, 일부러 같은 값을 만드는 공격이 알려져 보안 용도로는 쓰지 않습니다. 그래도 옛 자료의 체크섬이나 전송 오류 확인에는 여전히 쓰이므로 두었습니다.
    SHA 계열은 브라우저에 내장된 crypto.subtle로 계산하고, MD5는 브라우저가 지원하지 않아 직접 구현했습니다(RFC 1321). 파일은 통째로 메모리에 올리지 않고 조각으로 읽어 계산하므로 수 GB 파일도 됩니다.

    자주 묻는 질문

    파일이 서버로 올라가나요?

    아니요. 해시 계산은 전부 브라우저 안에서 이뤄지고 파일은 어디로도 가지 않습니다. 인터넷을 끊어도 동작합니다. 그래서 내부 자료나 설치 파일처럼 큰 파일도 안심하고 넣을 수 있습니다.

    값이 배포처와 달라요

    먼저 알고리즘이 같은지 보세요(SHA-256 값과 MD5 값은 당연히 다릅니다). 같은데도 다르면 내려받기가 중간에 끊겨 파일이 불완전하거나, 다른 버전을 받은 것입니다. 다시 내려받아 보세요. 그래도 다르면 그 파일을 실행하지 마세요.

    대조할 체크섬에 "sha256: " 같은 접두어가 붙어 있어요

    그대로 붙여 넣어도 됩니다. 16진수가 아닌 글자와 공백은 무시하고 비교합니다. "파일명 해시" 형식으로 한 줄을 통째로 붙여도 해시 부분만 찾아 대조합니다.

    큰 파일은 얼마나 걸리나요?

    보통 컴퓨터에서 1GB에 몇 초 정도입니다. 진행률을 표시합니다. 계산할 해시를 여러 개 켜면 그만큼 더 걸립니다.

    글의 해시는 어디에 쓰나요?

    프로그래밍이나 설정에서 특정 문자열의 해시가 필요할 때, 또는 두 긴 글이 완전히 같은지 짧은 값으로 비교할 때 씁니다. 글은 UTF-8 바이트로 바꿔 계산하므로 다른 도구와 같은 값이 나옵니다.
